# Ayame Editor — UI配置の理由 (UX Rationale)

全メニュー・全UIコンポーネントについて「何が・どこに・なぜその位置か」を固定するドキュメント。
デザイン(Figma / `figma/ayame-editor-design.use-figma.js`)と実装(`crates/ayame-cli/web/`)はこの文書に従う。
ズレを見つけたら、直すのはこの文書ではなく実装かデザインのほう(意図的に変える場合はここを先に更新する)。

## 設計原則

1. **エディタ面積が最優先** — 対象は巨大ファイル。常設クロームは「タイトル行・ツールバー・タブ・ステータス」の4行だけ。それ以外(検索・ダイアログ)はエディタ面に浮かべ、レイアウトを動かさない。
2. **頻度が位置を決める** — 毎分使うもの(Undo/Redo、エクスプローラー開閉)は左上のツールバー。たまに使うもの(ソート・置換・差分)は「ツール ▾」に畳む。設定・キー設定はメニューの中。
3. **同じ情報を2箇所に出さない** — ファイル名はタブが持つ。行数・サイズはエクスプローラーの極小メタとツールチップが持つ。ステータスバーには「今この瞬間の状態」だけ。
4. **フィードバックは常に見える場所へ** — 操作結果(保存・コピー・エラー)はステータスバーの専用領域(`#st-msg`, aria-live)に出す。検索バーの中など「開いていないと見えない場所」には出さない。
5. **破壊的操作は入力を1画面に集める** — ソート/置換/ケース変換は連続プロンプトではなく1枚のフォームダイアログ。暗黙のオプション継承(検索バーのトグル状態など)はしない。

## 画面レイアウト (上から下へ)

| 領域 | 内容 | なぜこの位置か |
|---|---|---|
| タイトル行 (`#menubar`) | 左: ロゴ / 右: メニュー4つ (ファイル・編集・選択・表示) | ロゴは左上=アプリの錨。メニューは右寄せにして中央を空け、タイトル行を「静かな行」に保つ(ユーザー決定 2026-07-02)。右端メニューのドロップダウンは右端アンカーで画面外にはみ出さない。 |
| ツールバー (`#toolbar`) | エクスプローラー開閉 / Undo・Redo / ツール ▾ | 開閉トグルは「レイアウトを変えるボタン」なので左端固定。Undo/Redo は最頻編集操作なのでその隣。ソート・置換・2ファイル差分・ケース変換は実行頻度が低く誤爆が痛いので「ツール ▾」に集約(ユーザー決定: explorerは開閉だけ、sort/diffはツール的な場所から)。検索・設定・ファイル名はここに置かない。 |
| タブバー (`#tabbar`) | 開いているファイル + 新規タブ | ファイル名の唯一の常設表示場所。dirty は名前の *とドットで示す。 |
| メイン | 左: エクスプローラー(既定は閉) / 右: エディタ | サイドバーは opt-in。ファイルサイズは 9px・50%透過の極小メタ(「情報でなく目印」)。 |
| エディタ内オーバーレイ | 検索バー(右上・浮動)、進捗オーバーレイ、iris水彩(左下・淡) | 検索はエディタの道具なのでエディタの中に出す(VS Code方式)。開閉でツールバーが動かない。右上なのは行頭(左)を隠さないため。 |
| ステータスバー | 行/列・エンコーディング・改行・保存状態・メッセージ / 右端: 索引 | 「今の状態」だけの最小構成(ユーザー承認済みの形)。詳細数値(行数・サイズ・索引統計)は各セグメントのツールチップへ。`#st-msg` は全操作フィードバックの常設出力先。 |

## メニュー全項目と文言

メニューバー(右寄せ)は**状態を持たない操作の目次**、ツールバーは**頻用ショートカット**。両者の重複は Undo/Redo とエクスプローラーのみ許す(メニューは網羅性のため)。

- **ファイル**: 新規テキスト `Ctrl+N` / 開く… `Ctrl+O` / ─ / 保存 `Ctrl+S` / 別名で保存… `Ctrl+Shift+S`
  - 「開く…」「別名で保存…」の「…」=ダイアログが出る印。
- **編集**: 元に戻す `Ctrl+Z` / やり直す `Ctrl+Y` / ─ / 検索 `Ctrl+F` / 行へ移動 `Ctrl+G`
- **選択**: すべて選択 `Ctrl+A` / コピー `Ctrl+C` / 切り取り `Ctrl+X`
  - 矩形選択は `Alt+ドラッグ`(ジェスチャ操作なのでメニュー項目にせずキー設定とREADMEに記載)。
- **表示**: エクスプローラー `Ctrl+B` / 検索バー `Ctrl+F` / ─ / 設定
- **ツール ▾ (ツールバー)**: ソート / 置換して保存 / 2ファイル差分 / ─ / 大文字化して保存 / 小文字化して保存 / ─ / キー設定
  - **ソート**: 保存先を聞かない。1枚のフォーム(キー列・数値比較・昇順/降順)→結果は**新しいタブ**に開く。元ファイルは不変(ユーザー決定: 「ソートして保存」ではなく「ソート」だけで終わる)。hover に「どこを見て並べるか」を明記。
  - **置換して保存 / ケース変換**: 出力先を書き換えるのでフォームに保存先パスを明示。
  - **2ファイル差分**: 「差分」でなくこの名前(現在ファイル ↔ 比較先の2ファイル比較であることを名前で示す。ユーザー決定)。

## 文言ルール

- 動詞は「〜して保存」= 別ファイル出力、「保存」= 上書き。破壊/非破壊が名前で分かること。
- ステータス: dirty は「未保存」/ クリーンは「保存済」。数値詳細はツールチップ。
- エラーは「何が + どうすればいいか」(例: 切り取り上限超過時は Delete を案内)。
- ボタンはアイコン+短い日本語ラベル。アイコンのみのボタンは `aria-label` と `title` 必須。

## アイコン

- 線画ストローク(丸キャップ)のオリジナルセット(`index.html` の `<symbol>` スプライト)。保存/ソート/差分には iris の花弁アクセント。文字を疑似アイコンにしない(「シンプルだが安っぽくしない」)。
- Figma側も同じ方針(Lucide風 1.8px stroke)。

## 対象外 (明示的な非目標)

- ブラウザ単体利用・オンライン公開・マルチユーザー編集(サーバはネイティブ窓のローカルUI層。既定バインドは 127.0.0.1)。
- CUI/ターミナルUI(CLIサブコマンドはアプリ内部ワーカーと開発用)。
- マルチカーソル編集(矩形選択+選択範囲置換で主用途を代替。将来検討)。
